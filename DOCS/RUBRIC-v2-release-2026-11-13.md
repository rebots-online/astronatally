# V2 release observation contract

Repository: rebots-online/astronatally. Authored before v2 release adapter code.
The operator's explicit separate-project, v2-host and above-2.0 instructions
supersede the old dual-host expectation in the immersive rubric. Architecture
§25 is the implementation contract; §24's 52-state design/function freeze stays.

1. Observe the Admin Manual project/resource inventory and separate credential
   scopes. Astronatally is a derivative of Natally-Ai-studio, not an alias or a
   replacement parent entry. Preserve shared credential provenance privately.
2. Record master integration before/after actual guest and auth rendering at
   desktop and phone widths. Observe one scene surviving rail changes, no
   overflow or page exceptions, and the same frozen layout/copy.
3. Confirm canonical Stitch files now reside under LIBS/UI/STITCH with the same
   master/CSS hashes and complete 52-state manifest. Legacy paths resolve to the
   same files, not independently modified copies.
4. Observe single-origin Google/email/SMS initiation without an old-domain
   handoff. Do not submit invented accounts, purchases or SMS identities. Native
   browser guard and receive-origin remain exact and share the configured v2
   origin; real native provider completion requires actual observation to claim.
5. Run the canonical build, preserving its actual UTC stamp. First new-lineage
   release starts automatically at2.1; build is epoch minutes modulo10000 and
   human display has five build digits. All artifacts have one release identity.
6. Observe publication/TLS/actual release badge at v2.astronatally.com. No release
   command publishes to astronatally.com or asknatally.online. Preserve original
   DNS records and compare any observed parent deployment without changing it.
7. DNS evidence must include complete provider getHosts, committed pre-change
   raw/normalized/zone/restore records, concurrency reread, exactly intended v2
   CNAME geo.surge.sh, full post-change comparison and resulting zone export.
   Request rejection is a pending operation, not a backup or successful change.
8. Produce actual web archive, Linux AppImage/deb/rpm, Windows executable/NSIS/
   MSI/MSIX, Android release APK/AAB and native symbols. Record command exits,
   files, sizes, hashes, package identities and actual signatures. Android must
   match the existing production signer and ZIP alignment requirements. MSIX
   identity/signature status must be stated accurately; no Store claim follows.
9. Preserve generated CC4 release manifests and current pointer. Actual served
   artifact bytes and manifest identity must match the built files/hashes. No
   placeholder link, stale package or build log containing private inputs.
10. Only after both publications, all native groups and served-artifact readback
    succeed does source MINOR advance exactly once with builtAt null. The built
    release remains unchanged; the source identity is ahead of it. A failed
    target or publication leaves source minor unadvanced.
11. Save actual build logs/inventory and delegated browser/screencast evidence
    under the named release/evidence directories. Type checks and package
    validation support the observation; no new unit tests substitute for it.
    Separate build, rendering, provider login/payment and market-adoption claims.
12. After the first actual successful web publication, observe the exact live
    URL/badge and pause the canonical process before native compilation. Resume
    only after the requested user review. EOF/other input yields review-pending
    exit75 with no native command or minor advancement. Retain unchanged UI
    review authorization across packaging-only retries.
